# Mobile API guide for Flutter (GetX)

Oct 14, 2026 · @houzifa Kroom

How the crew app (drivers and paramedics) and the citizen app talk to the EMR-MR backend, written for a Flutter team using GetX.

## Project structure

Build one app per role group:

- the **crew app** for `DRIVER` and `PARAMEDIC` (`clientApp: crew_app`);
- the **citizen app** for `CITIZEN` (`clientApp: citizen_app`).

They can share a `core` package. Services that live for the whole session are permanent GetX services; screens get their controllers through route bindings.

```
lib/
  app/            routes.dart, initial_binding.dart, translations/ (ar, en), theme.dart
  core/
    api/          api_client.dart (Dio), api_error.dart, auth_interceptor.dart
    services/     session_service.dart, device_service.dart, outbox_service.dart,
                  live_service.dart (STOMP), gps_service.dart, push_service.dart
  modules/
```

## API client (Dio + Retrofit)

The app makes every call through one Dio instance:

- an interceptor adds the token and refreshes it on `401`;
- Retrofit interfaces generated by `retrofit_generator` give typed calls;
- models use `json_serializable`.

There is no typed OpenAPI file for crew and citizen endpoints yet, so write the models by hand from this guide. When the backend publishes `openapi-crew.json`, fields will be added, never removed. Make fields nullable wherever this guide says they can be null. `json_serializable` ignores extra JSON keys, so new server fields will not break the app.

Basics:

- **Base URL:** `http://localhost:8080` in development (Android emulator: `http://10.0.2.2:8080`). Every path starts with `/api/v1`.
- **Data:** JSON in and out; times are ISO-8601 UTC.
- **Auth:** `Authorization: Bearer <accessToken>` on everything except login, verify, refresh, forgot and reset password, and citizen sign-up.
- **Tokens:** the access token lives 15 minutes. The refresh token lives 7 days and stays the same when you refresh. Keep it only in `flutter_secure_storage`.

Add these to `pubspec.yaml`: `dio`, `retrofit`, `json_annotation`, `get`, `flutter_secure_storage`, `uuid`. Under `dev_dependencies` add `retrofit_generator`, `json_serializable`, `build_runner`. Generate with `dart run build_runner build -d`.

### Dio setup and token refresh

```dart
class ApiClient extends GetxService {
  late final Dio dio;
  late final AuthApi auth; late final CrewApi crew; late final CitizenApi citizen;
  Completer<String?>? _refreshing;

  @override
  void onInit() {
    super.onInit();
    dio = Dio(BaseOptions(
      baseUrl: const String.fromEnvironment('API', defaultValue: 'http://10.0.2.2:8080'),
      connectTimeout: const Duration(seconds: 10), receiveTimeout: const Duration(seconds: 20)));
    dio.interceptors.add(QueuedInterceptorsWrapper(
      onRequest: (o, h) {
        final t = Get.find<SessionService>().accessToken;
        if (t != null && o.extra['public'] != true) o.headers['Authorization'] = 'Bearer $t';
        h.next(o);
      },
      onError: (e, h) async {
        final o = e.requestOptions;
        if (e.response?.statusCode == 401 && o.extra['public'] != true && o.extra['retried'] != true) {
          final t = await _refresh();
          if (t != null) {
            o.headers['Authorization'] = 'Bearer $t'; o.extra['retried'] = true;
            return h.resolve(await dio.fetch(o));
          }
          Get.find<SessionService>().signOut(reason: e.response?.data is Map ? e.response!.data['code'] : null);
        }
        h.next(e);
      },
    ));
    auth = AuthApi(dio); crew = CrewApi(dio); citizen = CitizenApi(dio);
  }

  /// One refresh at a time; concurrent 401s wait for the same answer.
  Future<String?> _refresh() async {
    if (_refreshing != null) return _refreshing!.future;
    final c = _refreshing = Completer<String?>();
    try {
      final rt = await Get.find<SessionService>().refreshToken();
      final t = rt == null ? null : (await auth.refresh(RefreshBody(rt))).accessToken;
      Get.find<SessionService>().accessToken = t;
      c.complete(t);
    } catch (_) { c.complete(null); }
    _refreshing = null;
    return c.future;
  }
}
```

Calls that need no token (login, verify, refresh, forgot, reset, sign-up) carry `@Extra({'public': true})`, so the interceptor neither adds a token nor retries them.

### Errors

Every error has the same body. Branch on `code`, and show `message_ar` or `message_en`:

```json
{"code":"STATUS_TIME_INVALID","message_ar":"…","message_en":"…","reference":"48cb62ba-…","time":"…",
 "fieldErrors":[{"field":"lon","code":"REQUIRED","message_ar":"…","message_en":"…"}]}
```

```dart
class ApiError implements Exception {
  ApiError(this.status, this.code, this.ar, this.en, this.reference, this.fields);
  final int status; final String code, ar, en; final String? reference; final List<Map<String, dynamic>> fields;
  String message([String? lang]) => (lang ?? Get.locale?.languageCode) == 'en' ? en : ar;
  String? fieldMessage(String field, [String? lang]) {
    final f = fields.where((x) => x['field'] == field).firstOrNull;
    return f == null ? null : ((lang ?? Get.locale?.languageCode) == 'en' ? f['message_en'] : f['message_ar']);
  }
  static ApiError of(Object e) {
    if (e is DioException && e.response?.data is Map && e.response!.data['code'] != null) {
      final b = e.response!.data as Map;
      return ApiError(e.response!.statusCode!, b['code'], b['message_ar'], b['message_en'], b['reference'],
          List<Map<String, dynamic>>.from(b['fieldErrors'] ?? const []));
    }
    return ApiError(0, 'NETWORK', 'تعذّر الاتصال بالخادم', 'Cannot reach the server', null, const []);
  }
}
```

In a controller: `try { … } catch (e) { final err = ApiError.of(e); error.value = err.message(); }`. Show `reference` only on unexpected errors, because support uses it.

### Retries and `Idempotency-Key`

These calls need a key: confirm, status, GPS, alerts, patient writes and citizen SOS.

- Make one UUID per user action, save it with the request in the outbox, and reuse the same key and the same body on every retry.
- A replay returns the original result and changes nothing.
- The same key with a different body gives `409 IDEMPOTENCY_CONFLICT`. Allowed key characters: `[A-Za-z0-9._:-]`, at most 128.

## Login and SMS code (both apps)

Login has two steps: the password, then a 6-digit SMS code. Generate a `deviceId` (UUID) once per install and keep it in secure storage. The account is bound to that device, and an admin or the hospital ER can block it if the phone is lost.

1. `POST /api/v1/auth/login` with `{username, password, deviceType: "mobile", clientApp: "crew_app" | "citizen_app", deviceId, appVersion: "1.0.0"}`. The reply is `{challengeId, expiresAt}`, and an SMS code is sent.
2. `POST /api/v1/auth/verify` with `{challengeId, code}`. The reply is `{accessToken, refreshToken, mustChangePassword}`.
3. If `mustChangePassword` is true, open the change-password screen. Only `POST /api/v1/auth/change-password` with `{oldPassword, newPassword}` (8–72 characters, at least one letter and one digit) works until it is done.
4. `GET /api/v1/me` returns `{id, username, fullNameAr, fullNameEn, role, preferredLanguage, scopes, stateCodes}`. Set the app language with `Get.updateLocale(Locale(me.preferredLanguage))`.

Other auth calls:

- **Resend code:** `POST /api/v1/auth/resend` with `{challengeId}`. Allowed after 60 s, at most 3 times. Show a countdown button.
- **Logout:** `POST /api/v1/auth/logout` returns `204`. Then clear secure storage, except `deviceId`.
- **Forgot password:** `POST /api/v1/auth/forgot-password` with `{username}` returns `202 {challengeId}`. Then `POST /api/v1/auth/reset-password` with `{challengeId, code, newPassword}` returns `204`.

```dart
class LoginController extends GetxController {
  final api = Get.find<ApiClient>(); final session = Get.find<SessionService>();
  final busy = false.obs; final error = RxnString(); final usernameError = RxnString();
  String? challengeId;

  Future<void> submitPassword(String username, String password) async {
    busy.value = true; error.value = null; usernameError.value = null;
    try {
      final c = await api.auth.login(LoginBody(
        username: username.trim(), password: password, deviceType: 'mobile', clientApp: AppConfig.clientApp,
        deviceId: await Get.find<DeviceService>().id(), appVersion: AppConfig.version));
      challengeId = c.challengeId;
      Get.toNamed(Routes.smsCode);
    } catch (e) {
      final err = ApiError.of(e);
      if (err.code == 'APP_UPDATE_REQUIRED') { Get.offAllNamed(Routes.forceUpdate); return; }
      error.value = err.message(); usernameError.value = err.fieldMessage('username');
    } finally { busy.value = false; }
  }

  Future<void> submitCode(String code) async {
    try {
      final t = await api.auth.verify(VerifyBody(challengeId: challengeId!, code: code));
      await session.start(t.accessToken, t.refreshToken!);
      if (t.mustChangePassword) { Get.offAllNamed(Routes.changePassword); return; }
      await session.loadMe();                // api.auth.me(); then Get.updateLocale(...)
      Get.offAllNamed(Routes.home);
    } catch (e) { error.value = ApiError.of(e).message(); }
  }
}
```

Login errors to handle:

| HTTP and code | What the app does |
| --- | --- |
| 401 `INVALID_CREDENTIALS` | Show the message |
| 400 `INVALID_CODE`, `CODE_EXPIRED`, `INVALID_CHALLENGE` | Ask again, or resend |
| 423 `ACCOUNT_LOCKED` | Locked for 30 min after 5 wrong passwords; show the message |
| 429 `SMS_RATE_LIMIT` | At most 5 codes per user per hour. Show the message; never retry in a loop |
| 429 `AUTH_RATE_LIMIT`, `RESEND_WAIT`, `RESEND_LIMIT` | Wait, then retry |
| 426 `APP_UPDATE_REQUIRED` | Force-update screen |
| 401 `DEVICE_BLOCKED`, `DEVICE_INVALID` | Sign out and show the message (the phone was blocked) |
| 403 `ACCOUNT_DISABLED` | Show the message |
| 403 `WRONG_CLIENT_APP` | "Use the other app" (for example, a citizen signing in to the crew app) |
| 503 `SMS_UNAVAILABLE` | Retry later |

## Crew app (DRIVER, PARAMEDIC)

### After login

| Action | Call | Reply |
| --- | --- | --- |
| Register the push token | `PUT /api/v1/devices/current/push-token` with `{pushToken}` | `{registered: true}` |
| Set or change the offline PIN (4–8 digits) | `PUT /api/v1/crew/pin` with `{pin}`, plus `oldPin` when changing it | `{saved: true}` |
| Check the PIN | `POST /api/v1/crew/pin/verify` with `{pin}` | `{verified: true}`; `401 PIN_INVALID`; after 5 wrong tries, `423 PIN_LOCKED` for 15 min |

The PIN unlocks the app while it is offline. Store only a verifier on the phone, never the PIN itself.

### Shift (scan the ambulance QR with `mobile_scanner`)

| Action | Call |
| --- | --- |
| Start a shift | `POST /api/v1/crew/shifts` with `{qrToken}` → `{id, ambulanceId}` |
| Join the current shift | `POST /api/v1/crew/shifts/current/join` with `{qrToken}` |
| End my shift | `POST /api/v1/crew/shifts/current/end` → `{shiftId, ended: true}` |

Errors: `SHIFT_ALREADY_ACTIVE`, `SHIFT_FULL`, `SHIFT_HAS_JOB` (you cannot end a shift with an open job), and `404` for an unknown QR.

### The job

`GET /api/v1/crew/job` returns `{job: null}` when there is no job. Otherwise it returns:

`{dispatchId, caseId, status, caseNumber, priority, complaint, directions, lon, lat, pinRadiusM, landmarkAr, landmarkEn, destinationHospitalId, hospitalAr, hospitalEn}`

The pin is approximate, so draw a circle of `pinRadiusM`, not just a point.

The app learns about a new job in three ways, in order of preference:

- the live queue (next section);
- polling every 15–30 s while on shift;
- push, once production FCM exists.

If the crew does not confirm in time, the hospital is alerted and phones them.

The job moves through statuses in a fixed order; the server refuses any other order:

```
sent → confirmed → en_route → on_scene → leaving_scene → at_hospital → completed
                                  └─────────→ completed  (treated at scene)
```

- **Confirm:** `POST /api/v1/dispatches/{dispatchId}/confirm` with no body.
- **Status:** `POST /api/v1/dispatches/{dispatchId}/status` with `{status, statusTime}`.
- Both require `Idempotency-Key`.
- `statusTime` is the moment the crew pressed the button, not the upload time. It cannot be earlier than the previous step (`STATUS_TIME_INVALID`) or more than 5 minutes in the future.
- A cancelled job arrives as `job.cancelled` and disappears from `GET /crew/job`.

**Offline outbox.** Every crew write goes into an ordered outbox first and is sent when there is a connection, with its key kept:

```dart
/// Saved to disk (hive/sqflite), so it stores path + JSON body rather than a Retrofit call.
/// Sent through the same Dio instance, so it gets the same token and refresh interceptor.
class OutboxItem {
  OutboxItem(this.path, this.body) : key = const Uuid().v4(), createdAt = DateTime.now().toUtc();
  final String path; final Object? body; final String key; final DateTime createdAt;
}

class OutboxService extends GetxService {
  final items = <OutboxItem>[].obs;           // persist in the real app
  bool _sending = false;
  Dio get _dio => Get.find<ApiClient>().dio;

  void add(String path, Object? body) { items.add(OutboxItem(path, body)); flush(); }

  Future<void> flush() async {
    if (_sending) return; _sending = true;
    try {
      while (items.isNotEmpty) {
        final i = items.first;
        try {
          await _dio.post(i.path, data: i.body, options: Options(headers: {'Idempotency-Key': i.key}));
          items.removeAt(0);
        } on DioException catch (e) {
          final s = e.response?.statusCode;
          if (s == null || s >= 500 || s == 429) return;   // offline or busy: retry later with the same key
          items.removeAt(0);                                // 4xx never succeeds: tell the crew
          Get.snackbar('', ApiError.of(e).message());
        }
      }
    } finally { _sending = false; }
  }
}

// JobController
void setStatus(String status) {
  final at = DateTime.now().toUtc().toIso8601String();
  job.update((j) => j!.status = status);           // optimistic
  Get.find<OutboxService>().add('/api/v1/dispatches/${job.value!.dispatchId}/status', {'status': status, 'statusTime': at});

```

Calls that are not queued (screens that read data, login, PIN check) use the Retrofit interfaces directly, for example `api.crew.job()`.

Call `flush()` when connectivity returns (`connectivity_plus`) and when the app resumes.

**GPS.** `POST /api/v1/crew/gps` takes a batch of 1–500 points and requires `Idempotency-Key`:

```json
[{"clientPointId":"<uuid per point>","recordedAt":"2026-10-13T05:44:48Z","lon":32.552,"lat":15.542,"accuracyM":6,"speedKmh":42,"headingDeg":45}]
```

The reply is `{saved, duplicates}`; a point sent twice is counted once. Send a batch every 15 s on a job and every 60 s while idle on shift. Phone GPS fills gaps when the ambulance tracker is silent, and the call centre sees how fresh it is.

```dart
class GpsService extends GetxService {
  final _buffer = <Map<String, dynamic>>[]; StreamSubscription<Position>? _sub; Timer? _timer;
  void start({required bool onJob}) {
    _sub?.cancel(); _timer?.cancel();
    _sub = Geolocator.getPositionStream(locationSettings: const LocationSettings(accuracy: LocationAccuracy.high, distanceFilter: 20))
        .listen((p) => _buffer.add({'clientPointId': const Uuid().v4(), 'recordedAt': p.timestamp.toUtc().toIso8601String(),
              'lon': p.longitude, 'lat': p.latitude, 'accuracyM': p.accuracy, 'speedKmh': p.speed * 3.6, 'headingDeg': p.heading}));
    _timer = Timer.periodic(Duration(seconds: onJob ? 15 : 60), (_) {
      if (_buffer.isEmpty) return;
      final batch = List.of(_buffer.take(500)); _buffer.removeRange(0, batch.length);
      Get.find<OutboxService>().add('/api/v1/crew/gps', batch);
    });
  }
  void stop() { _sub?.cancel(); _timer?.cancel(); }
}
```

On Android, background location needs a foreground service with a notification, plus the permissions `ACCESS_FINE_LOCATION`, `ACCESS_BACKGROUND_LOCATION` and `FOREGROUND_SERVICE_LOCATION`. On iOS, enable the `location` background mode.

**Pre-arrival alert (new).** `POST /api/v1/dispatches/{dispatchId}/alerts` with `{type, note}`.

- `type` is `stroke`, `stemi`, `trauma`, `sepsis`, `cardiac_arrest`, `obstetric` or `other`.
- Put one large button per type on the job screen and send it through the outbox.
- `403 OUTSIDE_SCOPE`: you are not on this job's shift. `409 DISPATCH_NOT_ACTIVE`: the job has ended.
- The receiving ER sees the alert with the ambulance ETA and acknowledges it.

### Patient care (PARAMEDIC)

These calls are allowed only while the crew's job for that case is open; after `completed` they return `403 PATIENT_ACCESS_DENIED`. Send each one with `Idempotency-Key`. Records are never edited: to correct one, send a new entry with `correctsId` set to the old entry's id.

| Action | Call | Notes |
| --- | --- | --- |
| Register a patient | `POST /api/v1/patients` | Unknown person: `{temporary: true, temporaryLabel, estimatedAge, fullNameAr, sex}`. Known: `nationalId` (6–15 digits), `fullNameAr`, `sex` (`male`, `female`, `unknown`), and optionally `fullNameEn`, `birthDate`, `phone`, `motherName`. Reply `{id, firstRecordStatus}` |
| Vital signs | `POST /api/v1/patients/{id}/observations` | `{observedAt, caseId, heartRate 20–250, respRate 2–80, spo2 40–100, onOxygen, systolic 40–300, diastolic 20–200 (below systolic), temperatureC 25–45, bloodGlucoseMmol 0.5–60, painScore 0–10, consciousness A, C, V, P or U}`. Send at least one value; out of range gives `400 DATABASE_RULE`. Check the ranges in the form first |
| Treatment | `POST /api/v1/patients/{id}/treatments` | `{givenAt, caseId, kind (medicine, procedure, oxygen, fluid, other), name, dose, route (oral, iv, im, sc, inhaled, topical, rectal, other)}` |

### Lost phone

When an admin or the hospital ER blocks the device, every call returns `401 DEVICE_BLOCKED`. Sign out, wipe tokens and cached patient data, and show the message.

## Citizen app (CITIZEN)

### Sign up

1. `POST /api/v1/citizen/sign-up/start` with `{phone: "+2499XXXXXXXX"}` returns `{challengeId, expiresAt}`, and an SMS code is sent.
2. `POST /api/v1/citizen/sign-up/finish` with `{challengeId, code (6 digits), nationalId, fullNameAr, fullNameEn, password}` returns `{id, identityStatus: "phone_verified", linkedPatient}`.
3. Log in as in the login section. The username is the phone number and `clientApp` is `citizen_app`.

Errors: `409 CITIZEN_PHONE_ACCOUNT_EXISTS` or `CITIZEN_ID_ACCOUNT_EXISTS` (offer "Log in" instead), `429 SIGNUP_RATE_LIMIT`, `400 INVALID_CODE` or `CODE_EXPIRED`.

### Profile

`GET /api/v1/citizen/me` returns `{fullNameAr, fullNameEn, phone, preferredLanguage, identityStatus, linkedPatient}`. `identityStatus` is one of:

- `phone_verified`;
- `id_card_verified` (checked in person at a hospital);
- `suspended` (after prank calls).

### SOS (the main screen)

One large red button. Get the best fix quickly (`geolocator`, high accuracy, 10–15 s timeout; fall back to the last known position), then send:

`POST /api/v1/citizen/requests` with `{lon, lat, accuracyM, note}` and an `Idempotency-Key`, so a retry never creates a second request. The reply is `{id, statusCode: "received"}`.

- `lon` and `lat` are required. `accuracyM` is 0–100000 and `note` at most 2000 characters.
- `429 CITIZEN_OPEN_REQUESTS`: the citizen already has 2 open requests in the last 30 minutes. Show the existing request instead.
- `403 CITIZEN_SUSPENDED`: show the message and the 999 number.
- With no data connection, offer "Call 999" (`url_launcher` with `tel:999`), and tell users with no internet that they can send an SMS to the SOS short code (number to be confirmed).

```dart
Future<void> sendSos(String? note) async {
  final key = const Uuid().v4();            // keep it for retries of this same press
  final p = await Geolocator.getCurrentPosition(locationSettings: const LocationSettings(accuracy: LocationAccuracy.high, timeLimit: Duration(seconds: 15)))
      .catchError((_) => Geolocator.getLastKnownPosition().then((v) => v!));
  final body = SosBody(lon: p.longitude, lat: p.latitude, accuracyM: p.accuracy, note: note);
  for (var attempt = 0; attempt < 3; attempt++) {
    try { final r = await api.citizen.sos(body, key); Get.offNamed(Routes.request, arguments: r.id); return; }
    on DioException catch (e) { if (e.response != null) { error.value = ApiError.of(e).message(); return; } }
    await Future.delayed(Duration(seconds: 2 << attempt));
  }
  offerCall999.value = true;
}
```

The call centre phones the citizen back; the app is not a chat. Tell the user: "Keep your phone free, the call centre will call you."

### Follow a request

- `GET /api/v1/citizen/requests?page=0&size=10` returns a page of `{id, startedAt, statusCode, statusAr, statusEn, updatedAt}`.
- `GET /api/v1/citizen/requests/{id}` returns `{statusCode, statusAr, statusEn, hospitalNameAr, hospitalNameEn, updatedAt}`.
- Show `statusAr` or `statusEn` from the server, not your own text.
- There is no live channel for citizens. Poll the open request every 10–15 s while its screen is open and stop when `statusCode` is `closed`.

| `statusCode` | Meaning |
| --- | --- |
| `received` | Request received; the call centre will call you |
| `finding_hospital` | Finding a hospital |
| `hospital_accepted` | A hospital accepted |
| `ambulance_coming` | The ambulance is on its way |
| `ambulance_arrived` | The ambulance has arrived |
| `to_hospital` | On the way to the hospital |
| `closed` | Request closed |

### Family and medical history

- Add a child or ward: `POST /api/v1/citizen/dependants` with `{childNationalId (6–15 digits), relation: "child" | "legal_guardian"}` returns `{id, status: "pending"}`. A hospital confirms the link in person.
- History: `GET /api/v1/citizen/history?page=0&size=10`. Add `patientId=` for a verified family member.
- Until the ID card (and the family link) is verified at a hospital, history returns `403 CITIZEN_HISTORY_NOT_VERIFIED`. Show that message with the steps to verify.

## Live updates and push

### Crew live job queue (STOMP)

- **Endpoint:** STOMP 1.2 over WebSocket at `/ws` (`ws://10.0.2.2:8080/ws` in development, `wss://` in production).
- **Connect:** send header `Authorization: Bearer <accessToken>` and heart-beats `10000,10000`.
- **Subscribe:** exactly `/user/queue/job`.
- **Events:** `{type, dispatchId, userId, time}` with `type` `job.new` or `job.cancelled`. On either, call `GET /api/v1/crew/job`. Ignore unknown types.
- **Token expiry:** when the access token expires, the server sends ERROR `message:UNAUTHORIZED` and closes. Reconnect with a fresh token, preferably before expiry.
- **Other errors:** the server sends ERROR and closes. Reconnect with backoff (1, 2, 4 … 30 s).

```dart
class LiveService extends GetxService {
  StompClient? _client; final jobEvents = Rxn<Map<String, dynamic>>();

  void connect() {
    _client?.deactivate();
    final token = Get.find<SessionService>().accessToken!;
    _client = StompClient(config: StompConfig(
      url: const String.fromEnvironment('WS', defaultValue: 'ws://10.0.2.2:8080/ws'),
      stompConnectHeaders: {'Authorization': 'Bearer $token'},
      heartbeatIncoming: const Duration(seconds: 10), heartbeatOutgoing: const Duration(seconds: 10),
      reconnectDelay: const Duration(seconds: 5),
      onConnect: (_) => _client!.subscribe(destination: '/user/queue/job',
          callback: (f) => jobEvents.value = jsonDecode(f.body!) as Map<String, dynamic>),
      onStompError: (f) async {                       // UNAUTHORIZED: refresh, then reconnect
        if (f.headers['message'] == 'UNAUTHORIZED') { await Get.find<ApiClient>().refreshNow(); connect(); }
      },
    ));
    _client!.activate();
  }
}

// JobController.onInit
ever(Get.find<LiveService>().jobEvents, (_) => loadJob());   // loadJob() = api.crew.job()
```

`refreshNow()` is the public form of `_refresh()` in the API client. Also call `connect()` after every proactive token refresh (about every 14 minutes), so the socket never runs on an expired token. Keep polling `GET /crew/job` every 30 s as a safety net while on shift.

### Push notifications

- After login, register the FCM token with `PUT /api/v1/devices/current/push-token` `{pushToken}`, and again whenever `onTokenRefresh` fires.
- **Not live in production yet.** The backend queues pushes for `job.new` (crew) and citizen status changes, but the production FCM sender is not implemented. Build the registration now; until push lands, rely on the live queue (crew) and polling (citizen).
- Data-only messages will carry `type` and the id (`dispatchId` or request `id`). Treat a push only as a hint to refetch; never trust its content for display.

### Screens off the happy path

| State | What the person sees |
| --- | --- |
| Loading | Grey blocks (`#E0E6E8`) in the shape of the content, with a soft shine; the screen reader hears that it is loading |
| Empty | A short title, one sentence, and the single next action when there is one |
| Error | The server message, a reference when one was returned, and Retry |
| No access | A plain statement that this account cannot open the screen, with no data behind it |

### Language and numbers

- English is left to right. Arabic is right to left, including the back button and the alignment of titles.
- Case numbers, phones, clocks and distances stay left to right inside an Arabic layout.
- A Sudan mobile number stored as `+249` plus 9 digits is shown the way it is dialled: a leading 0 and those 9 digits. `+249999964082` is shown as `0999964082`. Always send `+249…` to the API.
- On a waiting list, mask the phone: country code, bullets and the last 3 digits (`+249 ••••••102`). On the case the person is handling, show the dialled number.

- A dark theme.
- A second brand green for buttons; green is for P4 only.
- Soft embossed (neumorphic) buttons; they fail contrast.
- Neon, purple-pink gradients, or a typeface other than IBM Plex Sans and IBM Plex Sans Arabic.
