# EMR-MR Mobile — Build Progress

Living log for the Flutter crew and citizen apps. **Update after every step**, so a fresh session can pick up exactly where the last one stopped.

## How to resume

1. Read this file top to bottom, then `docs/mobile-app.md` (the API + UI contract).
2. `cd mobile && flutter pub get` (pub workspace; resolves all three packages).
3. `cd packages/emr_core && dart run build_runner build -d` if models/APIs changed.
4. `flutter test` in each of `packages/emr_core`, `apps/crew_app`, `apps/citizen_app`.
5. Continue with the first unchecked item under **Milestones**.

## Key decisions (ADR-lite)

| # | Decision | Why |
| --- | --- | --- |
| D1 | Pub workspace monorepo, one shared `emr_core` package | Guide asks for a shared core; workspace gives one lockfile and one resolution |
| D2 | GetX for DI/routes/state, Dio + Retrofit + json_serializable | Mandated by `docs/mobile-app.md` |
| D3 | Repositories between controllers and Retrofit APIs | Controllers test against fakes; API changes stay in one layer |
| D4 | Storage behind interfaces (`SecureStore`, `KeyValueStore`, `OutboxStore`) | Unit tests run in pure Dart with in-memory fakes |
| D5 | Outbox persisted in Hive CE (maintained Hive fork), JSON maps, no adapters | Works offline 24 h+ (NFR-05); testable with a temp dir |
| D6 | Outbox items may reference earlier items' results (`{ref:<localId>}` in path/body) | Paramedic can register a patient and record vitals while offline |
| D7 | Offline PIN: only a salted PBKDF2-SHA256 verifier stored on device | Guide: never store the PIN itself |
| D8 | Login handles `step: signed_in` as well as `sms_code` | Backend `LoginResult` can skip SMS when 2FA is off |
| D9 | `lucide_icons_flutter` instead of `lucide_icons` | `lucide_icons` caps SDK < 3.0 and does not resolve on Dart 3.11 |
| D10 | Light theme only; tokens from `docs/mobile-app.md` (newer than the pptx palette) | Must match the staff web portal |
| D11 | Times stored/sent in UTC, shown in Sudan time (UTC+2) | SRS BR-10 |
| D12 | Fonts bundled as static TTFs (IBM Plex Sans + Arabic, 400/500/600/700) | Guide forbids runtime font download |

## Backend facts verified live (2026-10-15)

Base used: `https://scored-rotary-lite-cam.trycloudflare.com` (temporary tunnel; changes on restart).

- `POST /auth/login` returns `LoginResult {step, challengeId, expiresAt, accessToken, refreshToken, mustChangePassword}`.
- `GET /me` includes `mustChangePassword`.
- `GET /crew/job` returns the job fields flat, or `{"job":null}`.
- `GET /citizen/requests` page has `totalElements: null` (use `hasNext`).
- `demo.citizen` logs in with the **username**, not the phone (phone login → `INVALID_CREDENTIALS`). Login screen accepts either.
- `GET /citizen/history` → `403 CITIZEN_HISTORY_NOT_VERIFIED` for the demo citizen.
- Validation errors carry `fieldErrors[{field, code, message_ar, message_en}]`.
- `demo.driver1` currently has a live job (status `leaving_scene`, KH-2026-000003). Do not mutate shared demo state casually.

## Requirements beyond the API guide (from SRS / planning / deck)

- Job accept is **swipe to confirm** (pocket-safe); full-screen alarm for a new job (AMD-02).
- Sync status always visible: "Online · all sent", "Offline · N waiting", "Sending x of y" (deck).
- Vitals: values outside normal range need a confirm before saving (AMS-03); hard limits from the API.
- Android 9+ (minSdk 28) for Release 1 (NFR-12). iOS kept buildable.
- Offline: keep ≥ 24 h of queued data, nothing lost or doubled (NFR-05, DoD).
- Citizen app has no SRS requirements; `docs/mobile-app.md` + API are its spec.
